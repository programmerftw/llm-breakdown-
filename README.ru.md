# От GPT-2 до Kimi K3

**Язык:** [English](./README.md) · Русский

Интерактивный образовательный сайт в одном файле, который наглядно показывает, как архитектура языковых моделей развивалась от GPT-2 до Kimi K3.

Сайт построен как визуальное повествование, а не как статичная статья в блоге: каждая важная идея представлена в виде интерактивной диаграммы, интерактивной мини-симуляции или разбора математических принципов. Цель проекта — помочь читателям понять не только, что изменилось, но и почему эти изменения стали необходимы по мере роста глубины моделей, длины последовательностей, нагрузки на память и сложности маршрутизации.

## Обзор проекта

Этот проект объясняет эволюцию архитектур через следующие идеи и механизмы:

- GPT-2 и декодерные трансформеры (decoder-only Transformers)
- механизм внимания (attention) с softmax и его квадратичная вычислительная сложность
- рост KV-кэша (кэша ключей и значений, KV cache) во время авторегрессионного декодирования (пошаговой генерации)
- линейное внимание (linear attention) и перегруппировка операций
- DeltaNet и гейтированное забывание (gated forgetting)
- Kimi Delta Attention (KDA)
- многоголовое латентное внимание (Multi-head Latent Attention, MLA)
- гибридные стеки KDA + MLA
- смесь экспертов (Mixture of Experts, MoE)
- Attention Residuals (AttnRes; внимание по глубине)
- итоговая архитектура Kimi K3

Русская версия сайта намеренно реализована в виде единственного файла `index.ru.html`, чтобы его было легко:

- прочитать от начала до конца
- развернуть как статический сайт
- разместить на Vercel или GitHub Pages
- создать форк и настроить проект под себя без системы сборки

## Зачем существует этот проект

В большинстве материалов о современных архитектурах моделей такие понятия, как KDA, MLA, MoE и AttnRes, рассматриваются по отдельности. Этот проект стремится представить их как единую историю инженерного развития.

Основная идея сайта такова:

1. Механизм внимания в стиле GPT обеспечивает эффективное извлечение информации из контекста, но требует всё больше ресурсов.
2. KV-кэш избавляет от повторных вычислений, но увеличивает расход памяти.
3. Линейная/рекуррентная память снижает вычислительные затраты на декодирование (пошаговую генерацию, decode), но вынуждена сжимать информацию.
4. KDA совершенствует рекуррентную память благодаря поканальному гейтингу (fine-grained gating).
5. MLA сохраняет возможность извлекать информацию на уровне отдельных токенов при меньшем размере кэша.
6. MoE увеличивает ёмкость модели, не активируя все параметры для каждого токена.
7. AttnRes помогает эффективнее масштабировать глубину благодаря извлечению информации из более ранних представлений.
8. Kimi K3 объединяет эти идеи в одной архитектуре промышленного масштаба.

Страница представляет собой подробный интерактивный разбор. Каждый раздел содержит поясняющий текст и одну или несколько иллюстраций.

### Разделы

`00 / Аннотация`
- Формулирует основной тезис страницы.

`01 / Основы`
- прямой проход GPT-2
- подробное устройство блока Transformer
- переключение между техническим и интуитивным режимами

`02 / Основы`
- матрица внимания с каузальной маской (causal attention matrix)
- пошаговый разбор токенов
- интерактивное уравнение механизма внимания с масштабированным скалярным произведением (scaled dot-product attention)

`03 / Основы`
- визуализация квадратичной вычислительной сложности
- отдельный разбор обучения, префилла (обработки входного контекста), декодирования (пошаговой генерации) и объёма памяти, занимаемого KV-кэшем

`04 / Основы`
- пошаговый разбор KV-кэша
- пошаговое сравнение префилла и декодирования

`05 / Линейная память`
- перегруппировка вычислений (re-association) в линейном внимании
- интуитивное объяснение ядерной функции (kernel function)

`06 / Линейная память`
- обновление состояния DeltaNet с интерактивными числовыми значениями

`07 / Линейная память`
- Gated DeltaNet и механизм забывания

`08 / Механизмы внимания Kimi`
- пути обработки данных в KDA
- переключение между интуитивным и исследовательским режимами
- панорамирование и масштабирование диаграммы

`09 / Механизмы внимания Kimi`
- конструктор гибридного стека
- сравнение требований KDA и MLA к памяти

`10 / Механизмы внимания Kimi`
- пошаговый разбор сжатия в латентное представление в MLA

`11 / Масштабирование и глубина`
- демонстрация маршрутизации в MoE

`12 / Масштабирование и глубина`
- сравнение Attention Residuals (AttnRes) со стандартным накоплением представлений через остаточные связи

`13 / Масштабирование и глубина`
- карта архитектуры Kimi K3
- интерактивная панель с подробностями о компонентах

`14 / Обобщение`
- карта эволюции всех механизмов

`15 / Обобщение`

- визуализация компромиссов при выборе размера чанка (chunk size)

`16 / Обобщение`
- сравнение механизмов на этапах префилла и декодирования

`17 / Обобщение`

`18 / Сравнения`

## Технологический стек

Проект намеренно минималистичен и не требует тяжёлого стека технологий.

- `HTML` для структуры
- `CSS` для оформления и компоновки
- `Vanilla JavaScript` (чистый JavaScript) для всей интерактивности и отрисовки
- `SVG` для диаграмм и динамических иллюстраций

Здесь нет ни сборщика, ни фреймворка, ни серверной части.

## Локальный запуск

Поскольку это статический сайт, проще всего открыть `index.ru.html` непосредственно в браузере.

Однако для тестирования обычно удобнее использовать локальный статический сервер:

```bash

```

Затем откройте:

### Вариант 2: Live Server в VS Code / Cursor

Откройте папку проекта в VS Code или Cursor и запустите `index.ru.html` с помощью расширения Live Server. Если редактор поддерживает встроенный предпросмотр статических страниц, можно использовать его.

## Развёртывание

Сайт статический, поэтому развернуть его несложно.

### Vercel

Рекомендуемый вариант, если вы пользуетесь Vercel.

1. Отправьте проект на GitHub.
2. Импортируйте репозиторий в Vercel.
3. Выбирать предустановку фреймворка не требуется.
4. Vercel должен автоматически обнаружить и опубликовать английский `index.html`; русская версия будет доступна по адресу `/index.ru.html`.
5. Запустите развёртывание.

### GitHub Pages

1. Отправьте проект в репозиторий GitHub.
2. Откройте репозиторий на GitHub.
3. Перейдите в `Settings` -> `Pages`.
4. В разделе `Build and deployment` выберите:
   - `Source`: `Deploy from a branch`
   - `Branch`: `main`
   - `Folder`: `/ (root)`
5. Сохраните настройки.
6. Дождитесь, пока GitHub опубликует сайт.
