00 / ОБЗОР

Дело не только в масштабе

Двадцать две тысячи пятьсот восемьдесят. Столько моделей GPT-2 помещается в Kimi K3. Но самое интересное за последние семь лет — не этот множитель, а то, что пришлось изменить внутри архитектуры, чтобы таким масштабом можно было пользоваться.

На этой странице вся линия развития собрана в интерактивных схемах. Каждый механизм показан наглядно, каждый практикум выполняет вычисления с конкретными значениями на небольших тензорах, а каждый архитектурный шаг появился потому, что предыдущий подход упёрся в ограничение: механизм внимания (attention) связывает каждый токен с каждым; память (memory) нужно хранить, обновлять и очищать; маршрутизация (routing) направляет ёмкость туда, где она нужна; остаточный поток (residual stream) переносит информацию через всю глубину сети.

01 / ОСНОВЫ

Отправная точка: GPT-2

GPT-2 (2019) — исходная модель: трансформер только с декодером (decoder-only Transformer), который предсказывает следующий токен по всему предшествующему контексту. Далее будем называть его декодерным трансформером. Каждая последующая архитектура в этой истории меняет именно этот каркас, поэтому сначала покажем весь конвейер.

Неэффективность, с которой всё начинаетсяПри генерации декодерный трансформер вычисляет представления для каждой входной позиции, но при декодировании (decode), то есть пошаговой генерации, используются только логиты последней позиции. Без кэширования эта работа повторяется для каждого нового токена — именно это исправляет KV-кэш (кэш ключей и значений) в §04.
02 / ОСНОВЫ

Механизм внимания — наглядно

Каждая позиция задаёт вопрос — формирует запрос (query), оценивает ключ (key) каждой видимой позиции и смешивает их значения (values). Матрица ниже выполняет настоящий расчёт: наведите указатель на токен, чтобы увидеть его запрос, ключи, оценки и полученную взвешенную смесь значений.

Внимание на основе масштабированного скалярного произведения (scaled dot-product attention)
\[ \htmlClass{kx-symSM}{\mathrm{softmax}}\!\Big(\tfrac{\htmlClass{kx-symQ}{Q}\,\htmlClass{kx-symKT}{K^{\top}}}{\htmlClass{kx-symDK}{\sqrt{d_k}}} \;+\; \htmlClass{kx-symM}{M}\Big)\,\htmlClass{kx-symV}{V} \qquad \htmlClass{kx-symSM}{\mathrm{softmax}}(x)_j=\frac{e^{x_j}}{\sum_i e^{x_i}} \]
03 / ОСНОВЫ

Квадратичная сложность — точная формулировка

Стоимость внимания нельзя выразить одним числом. Обучение, префилл (prefill, обработка входного контекста), декодирование и память KV-кэша масштабируются по-разному — именно смешение этих величин и вносит путаницу в обсуждение O(N²). Изменяйте длину последовательности и наблюдайте за каждой стоимостью отдельно.

—ячеек оценок = N²
—пикселей матрицы при 18 px/ячейку
—экранов по ширине (1512 px)
Четыре отдельные составляющие стоимости [ИСТОЧНИК] Обучение — до FlashAttention (2022) полные матрицы оценок N×N материализовались в памяти.
Префилл — весь промпт обрабатывается сразу: O(N²) операций расчёта оценок на слой.
Декодирование — каждый шаг читает весь KV-кэш: 2·N·D чтений + 2·D записей в память с высокой пропускной способностью (High Bandwidth Memory, HBM); узким местом служит пропускная способность памяти, а не производительность вычислений (FLOPS).
KV-кэш — растёт как O(N) и при длинном контексте может стать узким местом из-за ограниченной пропускной способности памяти.
04 / ОСНОВЫ

KV-кэш

Без кэширования при добавлении каждого сгенерированного токена модель заново вычисляла бы проекции всех предыдущих токенов. Хранение их ключей и значений устраняет эту лишнюю работу — такое хранилище и называется KV-кэшем. Пройдите по шагам генерации и проследите за его ростом, а затем сравните с состоянием постоянного размера, которое вводит линейное внимание в §05.

05 / ЛИНЕЙНАЯ ПАМЯТЬ

Перегруппировка вычислений в линейном внимании

Softmax применяет нелинейность после произведения q·k, связывая каждый запрос с каждым ключом. Линейное внимание (linear attention) применяет отображение признаков к q и k по отдельности, поэтому произведение можно перегруппировать: вместо матрицы N×N ключи и значения сворачиваются в состояние фиксированного размера d×d.

Линейное внимание с отображением признаков φ(x) = elu(x) + 1 [ИСТОЧНИК]
\[ o_t=\frac{\htmlClass{kx-symPhi}{\phi(q_t)}^{\top}\big(\sum_{i\le t}\phi(k_i)\,v_i^{\top}\big)}{\phi(q_t)^{\top}\big(\sum_{i\le t}\phi(k_i)\big)} \]

Что сохраняется

Фиксированное состояние d×d для каждой головы: память при декодировании составляет O(1) на шаг, растущего KV-кэша нет. Сохраняются те же три шага внимания: сделать оценки неотрицательными, нормализовать их и взять взвешенное среднее значений.

↔

Чем приходится поступиться

ELU+1 задаёт альтернативное, менее выразительное ядро, а не универсально точное приближение softmax, поэтому качество зависит от архитектуры и задачи. А поскольку состояние только накапливается, ассоциации со временем начинают мешать друг другу (§06).

06 / ЛИНЕЙНАЯ ПАМЯТЬ

DeltaNet — запись только разницы

У состояния фиксированного размера конечна ассоциативная ёмкость: по мере добавления записей растёт интерференция, и новые ассоциации всё сильнее мешают старым. Когда N намного больше размерности состояния, «бесконечное добавление новых ассоциаций в память конечного размера… неизбежно достигнет предела» (Schlag et al., Linear Transformers Are Secretly Fast Weight Programmers — «линейные трансформеры на самом деле являются программистами быстрых весов»). Решение DeltaNet: перед записью прочитать, что уже хранится по этому ключу, а затем записать только разницу — дельту.

Дельта-правило, репараметризованное для параллельных блоков [ИСТОЧНИК]
\[ \htmlClass{kx-symS}{S_t}=\big(\htmlClass{kx-symI}{I}-\htmlClass{kx-symB}{\beta_t}\,\htmlClass{kx-symKt}{k_t}\htmlClass{kx-symKt}{k_t^{\top}}\big)\htmlClass{kx-symS}{S_{t-1}}+\htmlClass{kx-symB}{\beta_t}\,\htmlClass{kx-symKt}{k_t}\htmlClass{kx-symVt}{v_t^{\top}} \]
07 / ЛИНЕЙНАЯ ПАМЯТЬ

Gated DeltaNet — учимся забывать

Дельта-правило может перезаписать память, только когда есть конкретная замена; оно не умеет очищать сразу несколько ассоциаций при смене контекста или ослаблять память, освобождая ёмкость. Gated DeltaNet добавляет идею из Mamba-2: перед каждой дельта-записью к предыдущему состоянию применяется вентиль затухания α.

08 / ВНИМАНИЕ KIMI

Kimi Delta Attention — центральный механизм

KDA — основа Kimi Linear: линейное внимание с дельта-правилом и вентилем, обеспечивающее тонко настраиваемое поканальное затухание. Вместо одного скаляра α модель обучается формировать Diag(αₜ) — отдельное значение затухания для каждого канала состояния. Переключайте пути ниже, чтобы проследить прохождение блока токенов через механизм.

Обновление состояния KDA — тонко настраиваемое диагональное вентильное управление [ИСТОЧНИК: Kimi Linear, arXiv:2510.26692]
\[ \htmlClass{kx-symS}{S_t}=\big(\htmlClass{kx-symI}{I}-\htmlClass{kx-symB}{\beta_t}\,\htmlClass{kx-symKt}{k_t}\htmlClass{kx-symKt}{k_t^{\top}}\big)\htmlClass{kx-symA}{\mathrm{Diag}(\alpha_t)}\;\htmlClass{kx-symS}{S_{t-1}}+\htmlClass{kx-symB}{\beta_t}\,\htmlClass{kx-symKt}{k_t}\htmlClass{kx-symVt}{v_t^{\top}} \]
Опубликованные результаты [ИСТОЧНИК]При одинаковой схеме обучения Kimi Linear (48 млрд параметров всего / 3 млрд активных, гибрид KDA:MLA 3:1) превосходит MLA с полным вниманием в проведённых оценках, уменьшает объём KV-кэша максимум на 75% и повышает пропускную способность декодирования до 6 раз при длине контекста 1 млн токенов.
09 / ВНИМАНИЕ KIMI

Гибридное внимание — зачем несколько механизмов?

Полное внимание адресно взвешивает все позиции, но платит за это растущим KV-кэшем; рекуррентные слои декодируют за O(1), но вынуждены сжимать информацию. Ответ Kimi — гибридный стек с повторяющимся соотношением 3 KDA : 1 MLA. В Kimi K3 в конце также добавлен отдельный слой Gated MLA. Соберите свой стек ниже и посмотрите, как меняется профиль памяти.

Глобальное извлечение

Слои MLA хранят сжатое представление каждого предыдущего токена, поэтому механизм softmax всё ещё может отдельно взвешивать каждую позицию контекста.

↔

Эффективная рекуррентность

Слои KDA переносят через всю последовательность состояние постоянного размера: декодирование O(1), кэш не растёт, но часть информации приходится вытеснять.

10 / ВНИМАНИЕ KIMI

Многоголовое латентное внимание — сжимаем кэш

При длинном контексте именно KV-кэш начинает определять расход памяти. Многоголовое латентное внимание (Multi-head Latent Attention, MLA) проецирует скрытое состояние токена x в общий компактный вектор cₜ = Wcxₜ. В кэше хранится cₜ, а ключи K и значения V восстанавливаются из него обучаемыми проекциями в исходную размерность (up-projections) во время внимания.

d = 4096, d_c = 512 на токен [УЧЕБНЫЙ ПРИМЕР: условные соотношения]. Для Kimi Linear опубликованы уменьшение объёма KV-кэша максимум на 75% и рост пропускной способности декодирования до 6 раз при контексте длиной 1 млн токенов [ИСТОЧНИК].

11 / МАСШТАБ И ГЛУБИНА

Смесь экспертов — ёмкость без лишних вычислений

Обучаемый маршрутизатор направляет каждый токен к нескольким экспертам, поэтому общая ёмкость модели может намного превышать объём вычислений на токен. В каждом MoE-слое модели Kimi K3 работают 898 экспертов: 2 общих для каждого токена и 896 маршрутизируемых, из которых для одного токена выбираются 16 [ИСТОЧНИК].

Разреженная маршрутизация — токен x активирует только своих top-k экспертов
\[ y \;=\; \sum_{e \,\in\, \mathrm{top}\text{-}k}\;\htmlClass{kx-symGe}{g_e(x)}\;E_e(x) \qquad \text{K3: } k=16 \text{ из } 896 \text{ маршрутизируемых} \]
2,8 трлнпараметров всего [ИСТОЧНИК]
≈104 млрдактивных параметров на токен [ИСТОЧНИК: публикации]
898экспертов в MoE-слое · 2 общих · 16 маршрутизируемых/токен
≈3,7%доля активных параметров: 104 млрд из 2,8 трлн

Во время обучения маршрутизатор также должен балансировать нагрузку между экспертами, иначе несколько экспертов заберут большинство токенов, а остальная ёмкость будет простаивать. В Stable LatentMoE модели K3 два общих эксперта сохраняют путь полной ширины, а 896 маршрутизируемых экспертов работают в латентном пространстве шириной 3584 — вдвое уже скрытой размерности 7168. Это снижает вычисления и обмен данными маршрутизируемого пути [ИСТОЧНИК].

12 / МАСШТАБ И ГЛУБИНА

Attention Residuals — внимание по глубине

В стандартном остаточном потоке коэффициент каждого добавляемого выхода равен 1. Если для наглядности считать величины вкладов сопоставимыми, условная нормированная доля одного слоя уменьшается с глубиной. Метод Attention Residuals (AttnRes) позволяет каждому слою извлекать нужное из предыдущих представлений вместо получения одной агрегированной суммы.

Стандартный вариант [ИСТОЧНИК]
\[ \htmlClass{kx-symHl}{h_l}=h_1+\sum_{i=1}^{l-1}f_i(h_i) \]

Только сложение, без избирательного доступа: каждый слой получает собственную накопленную сумму, но не может отдельно выбрать прошлое представление.

→
AttnRes [ИСТОЧНИК]
\[ \htmlClass{kx-symHl}{h_l}=\htmlClass{kx-symAl}{\alpha_0}\,h_1+\sum_{i=1}^{l-1}\htmlClass{kx-symAl}{\alpha_i}\,f_i(h_i), \quad \alpha=\mathrm{softmax}(q\!\cdot\!k) \]

Каждый αᵢ — нормированный вес softmax, полученный из оценки q·kᵢ для предыдущего остаточного состояния.

Block AttnRes в Kimi K3 [ИСТОЧНИК]93 слоя разделены на 8 блоков размером 12 слоёв, причём последний блок неполный, а эмбеддинг служит дополнительным источником. Внутри каждого слоя Block AttnRes применяет softmax-внимание к суммам завершённых блоков и к текущей частичной сумме. Так число хранимых представлений уменьшается с O(L) до O(числа блоков), сохраняя избирательный доступ по глубине.
